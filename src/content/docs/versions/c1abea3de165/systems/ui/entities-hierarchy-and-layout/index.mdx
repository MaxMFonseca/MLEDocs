Layout is a tree calculation over retained components. The hierarchy supplies coordinate space and ordering; a container or renderable supplies size; target components constrain the result. Most hard-to-diagnose UI failures come from changing one layer without invalidating the other.

## Relationship ownership

`Relationship` stores a parent plus a circular doubly linked sibling ring and the parent's first child/count. Creating a child allocates it in the same UI registry, gives it `Relationship` and `Bounds`, attaches it, applies `children_base` before the child's own table, then calls its one-shot `on_create`.

Names may not contain `.`. `getChild` follows immediate names; IDs scan the registry; tag/name recursive queries descend the tree. Reparenting unlinks the entity first and invalidates both the old/new layout path. Destruction recursively runs `on_destroy` and removes descendants. Calling `Entt::destroy()` only marks the element for the end of the update.

Suffix-only forms use `1` (or `100` for percentages); explicit percent values are divided by 100. Origins also accept `l`/`t` = 0, `x`/`c` = 0.5, and `r`/`b` = 1. A sibling dependency names an element in the same parent, optionally followed by `:<value>`; a missing sibling logs an error and leaves the dependency entity null.

## Container choice

`ListContainer` lays out children horizontally, vertically, or reversed; it supports wrap, main-axis justification, cross alignment, gaps, and flex shares. `FreeContainer` positions children independently and also carries vertical scroll state. A renderable installs `SizeProvider`, so an entity should not combine incompatible sizing providers.

## Invalidation direction

An **internal** request means this entity's calculated content may change. The intended shape is selective propagation when the entity can fit content, but that is not the pinned behavior: `Entt::hasFitSize` returns true on every path, including its final fallback. Therefore every internal bounds request currently propagates externally. An **external** request recursively climbs through ancestor internal requests until the root, where it becomes a full root/layout request. In this snapshot, treat invalidation as broad and do not rely on fixed-size descendants containing it.

The bounds phase resolves external requests first, recalculates the affected entity or whole tree, invokes `on_resized`, clears resize flags, and resets cached size providers.

Dependencies and child layout are order-sensitive. Define referenced siblings before relying on them, and avoid mutating the hierarchy from a size provider. The exhaustive aliases and table shapes belong to the planned **UI element keys** and **UI layout values** references.
