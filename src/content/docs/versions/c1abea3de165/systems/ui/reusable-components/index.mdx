Shipped components are Lua files that return a factory function. The factory returns an ordinary UI element fragment; callers attach it through `comp`, combine it with their element's `style`, structural `children`/`c`, names, and local overrides, and let normal table-to-entity construction do the rest.

## Module execution is not package loading

The engine's `require`, `requirePath`, and `tryRequire` call `script_file`. They do not use Lua package `require` or `package.loaded`; requesting a component re-executes the file. Use the accepted dotted or slash-like resource path already demonstrated by shipped scripts, and keep module-level mutable state deliberate. `tryRequire` protects a missing file (`NOT_FOUND`) only; syntax and runtime errors in an existing file still escape.

## Composition conventions

- Return a new table for every instance. Copy caller-owned row/option tables when later mutation would leak across instances.
- Put private retained state under `table`, callable behavior under `fn`, and stable traversal identifiers under `name` or `id`.
- Use `comp` to merge one reusable fragment into the host. `style`, `styles`, `children`, `c`, `child`, and `add_child` are structural application keys, not ECS components themselves.
- Child names must match every `getChild()` call. IDs enter the UI-wide lookup and therefore carry broader collision/cleanup consequences.
- Callback closures belong to their Lua state. Do not move them across the Client state and rendering-system auxiliary states.
- After changing child count, content, or bounds-affecting properties, request the appropriate internal/external bounds update.

These are source-shipped patterns, not a compatibility-stable widget toolkit. The strongest tests cover filtering and scrolling. [`filterable_list.lua`](https://github.com/MaxMFonseca/MLE/blob/c1abea3de165032fe064300340807b7a6af388f8/res/lua/ui/comp/filterable_list.lua) is the best example of validation, defensive copying, child replacement, state, and invalidation in one component.
