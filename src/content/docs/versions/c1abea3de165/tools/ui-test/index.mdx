UI Test is the Client's interactive catalog for retained UI behavior. Its pages are demonstrated, not a guarantee of automated support. The table distinguishes them from related Core assertions: a page can visually exercise integration that no automated test asserts end-to-end.

## Enter and navigate

The Client layer initializes the UI, loads the UI Test Lua shell, and renders it through the normal Client/render path. `Layer.lua` composes a one-active `multipanel`. Left and Right change pages; Escape invokes the application-owned return callback. [Interactive Client](../interactive-client/) covers the exact build, launch, and layer-selection entry points for this snapshot.

## Resources

UI Test uses `tests/Client/res/textures/ui/animation_sprite_sheet.png`, `nine_slice_panel.png`, and the `progress_bar/` textures. Resource aliases such as `i/ui/...` come from the Client's configured directory mapping; copying a Lua fragment without that mapping is incomplete.

## Evidence boundary

Core tests directly assert animation math and completion, scroll clamping/overflow, sprite UV parsing, nine-slice parsing, bounds, scissor, text, and input primitives. Client UI Test launches real integration examples, but its visual outcomes and controls are interactive demonstrations rather than automated Core assertions. See [`UITest.cpp`](https://github.com/MaxMFonseca/MLE/blob/c1abea3de165032fe064300340807b7a6af388f8/tests/Client/src/layers/UITest.cpp) and the full [`Layer.lua`](https://github.com/MaxMFonseca/MLE/blob/c1abea3de165032fe064300340807b7a6af388f8/tests/Client/res/lua/ui/ui_tests/Layer.lua).
