Fixtures are committed evidence inputs, not a blanket compatibility promise. A test loading one PNG, shader, Lua module, WAV, GLB, or cubemap family does **not** make every byte layout a supported public format. Keep provenance, the consumer, and the evidence class together when changing a resource.

## Regenerate deterministic audio

Install the pinned generator requirements in an isolated Python environment, then verify without modifying committed resources:

```bash
python -m pip install -r tests/Client/audio_requirements.txt
python tests/Client/tools/generate_audio_fixtures.py --verify
```

`--verify` generates into a temporary directory and byte-compares the complete expected set. The generator uses a fixed seed and 48 kHz sources. `audio_manifest.json` records filenames, hashes, rate, channel/frame metadata, roles, and generated peaks where applicable. `corrupt.wav` is a deliberately truncated RIFF header used as a negative fixture; do not “repair” it.

The generated WAV family is consumed only by the interactive Client Audio Test. Core audio tests construct state and sample data in memory; they do not load these generated WAV files. A generated cue can therefore support an interactive scenario without becoming automated Core evidence.

Running the script without `--verify` writes the committed output directory. Do that only when intentionally changing fixture semantics.

## Regeneration and review workflow

1. Identify the owning test or interactive page and state why existing fixtures cannot express the case.
2. Change the generator when the family is generated; do not hand-edit generated WAV bytes or the manifest.
3. Regenerate, then immediately run `--verify`.
4. Review the committed binary set, `audio_manifest.json`, added/removed filenames, hashes, duration/channel properties, and the owning test or demonstration.
5. Run the narrow automated suite or record the exact interactive action. Byte equality does not prove audible or visual correctness.
6. Update [Tests and interactive pages](../../contributing/tests-and-interactive-pages/) ownership and documentation when a new family is introduced.

For hand-authored Lua/shader fixtures, review the source diff and the consuming assertion. For model, image, or cubemap binaries, preserve license/support files and record their provenance. A support note or license is metadata—not an automated test.
