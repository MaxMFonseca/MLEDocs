`scripts/envsetup.sh` supplies shell functions, not installed commands. Source it from the MLE repository root, where it records `_MLE_ROOT`; direct execution exits with status `1`, and sourcing outside a directory containing `README.md` returns `1`. The procedure is [set up a working tree](/MLEDocs/versions/c1abea3de165/start-here/setup/). This reference records source behavior rather than running helpers.

## `mle_gen_docs`: obsolete and excluded

> **Obsolete workflow — excluded from MLEDocs.** `mle_gen_docs` invokes the pinned repository's legacy Doxygen input and prints its legacy output location. Its generated Doxygen material is not authority for this documentation site and must not be used to generate, validate, or extend MLEDocs content.

## `mle_run_test`: upstream path-safety limitation

> **Upstream safety limitation — trusted segments only.** Pass `-t` and `-n` only trusted single path segments: no `/` or `\` path separators, and neither `.` nor `..`. The helper interpolates both values without validation into a recursive deletion path and later directory and executable paths. A separator or dot segment can normalize the deletion and delete outside the intended generated target tree; its unguarded intermediate `mkdir` and `cd` calls can leave later commands in the wrong working directory, and subsequent commands can mask the failure status. Validate both arguments upstream before broader use. Until then, never pass untrusted values to this helper.

## Destructive and masked-result boundaries

`mle_clean` is destructive: it removes the exact `${_MLE_ROOT}/build` directory recursively, losing every generated build configuration there, then removes `compile_commands.json` and `latest.log` from the current invocation directory. It does not remove same-named files in another directory and does not repair prerequisites, submodules, or tool discovery.

For trusted single-segment inputs, `mle_run_test` first deletes the selected `build/<build_type>/tests/<name>/res` tree recursively, so any generated links or files in that tree are lost before it recreates its six resource-kind directories. The source does not enforce that containment: separators or dot segments in either path argument can escape it. Its unguarded resource-directory work, hidden `mle` and `i` link errors, later link operations, and final `echo` can also hide the originating failure. Read the program output and selected log to evaluate the run.

For shader work, missing or empty directories can lead to the successful `No shaders found.` result (`0`). Fully current outputs still cross `find` and `xargs` but do so without invoking `glslangValidator`. `Some shaders failed.` means a compiler or parallel job failed (`1`); a missing shader directory is reported and skipped rather than classified as a compiler failure.
