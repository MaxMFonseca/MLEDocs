This is a curated lookup for integration decisions, not a method-by-method C++ reference or stability promise. Every command is produced on a caller thread, copied into `CommandMailbox`, and consumed by the audio thread. `enqueueCmd` returns `void`; failures after submission are logged.

## `PlayParams`

Defaults are position `(0,0,0)`, volume `1`, velocity `(0,0,0)`, pitch `1`, all millisecond fields `0`, `spatial=false`, and bus `0`. Streams use volume, pitch, start offset, duration, fade-in, position/velocity/spatial, and bus. One-shots use volume, pitch, position/velocity/spatial, and bus; their time/fade fields are not read.

## Mailbox and selection outcomes

- `CommandSubmitResult`: `ACCEPTED`, `FULL`, `CLOSED`. These are internal mailbox outcomes; `enqueueCmd` converts rejection to warnings.
- `VoiceRejectReason`: `NONE`, `INVALID_BUS`, `ZERO_PRIORITY`, `BUS_CAP`, `INSUFFICIENT_PRIORITY`, `NO_ELIGIBLE_VICTIM`.
- `StreamGroupRejectReason`: `NONE`, `EMPTY`, `TOO_MANY`, `INVALID_SLOT`, `DUPLICATE_SLOT`.
- `RampCompletion`: `RampCompletion::NONE` reports no terminal action; `RampCompletion::STOP` tells the stream updater to stop and clear the slot after a fade reaches zero.

Supporting types are `AudioEngine`, `Cmd`, `CommandMailbox`, `AudioThreadStartup`, `WavData`, `SourcePlaybackState`, `SampleWindow`, `ValidatedStreamStart`, `VolumeRamp`, `RampCompletion`, `RampAdvance`, `BusVoicePolicy`, `VoiceMetadata`, and `VoiceSelection`. `RampAdvance` returns the current volume plus a one-time `RampCompletion` from `advanceRamp`. Their ownership semantics are explained on [Lifecycle and command flow](../../systems/audio/lifecycle-and-command-flow/) and [Playback and streaming](../../systems/audio/playback-and-streaming/).

The string form of `startStream` is accepted despite its error text saying the expected type is a table. Lua exposes no group start, spatial fields, time window, listener, distance, state query, or completion callback.

## Runtime-configuration keys

The debug listeners are `audio.play_one_shot`, `audio.start_stream`, `audio.stop_stream`, `audio.pause_stream`, `audio.resume_stream`, `audio.set_volume`, and `audio.stop_all`. Values are space-split strings. `audio.start_stream` actually requires three tokens—sound name, slot ID, and bus—but its rejection message reports two arguments (`requires 2 arguments`) while printing all three placeholders. Invalid numeric text silently falls back to slot/bus `0` or volume `1`. These keys are debug surfaces, not a structured runtime API.
