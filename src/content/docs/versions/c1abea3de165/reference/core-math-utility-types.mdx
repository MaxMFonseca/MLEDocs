This is a curated lookup for names that recur across the runtime foundations. It summarizes the pinned definitions rather than reproducing declarations. Each row links to the owner page that explains lifecycle, errors, threading, or edge behavior. Header visibility and inclusion here are **not an API or SDK stability promise**.

The defining status vocabulary is in [`Result.h`](https://github.com/MaxMFonseca/MLE/blob/c1abea3de165032fe064300340807b7a6af388f8/src/mle/core/Result.h); the other metadata source links above are equally pinned to this snapshot.

`unwrap` consumes an rvalue `Expected<T>` and aborts through Core on error. `check` aborts only for statuses where `isError` is true. Assertion macros are debug diagnostics and release invariants, not recoverable result conversion.

| Identifier | Meaning | Owner page |
| --- | --- | --- |

| `Rectf`, `Recti` | Position plus normalized non-negative size; bounds are inclusive. | [Geometry and intersections](/MLEDocs/versions/c1abea3de165/systems/math/geometry-and-intersections/) |
| `NearFar` | Pair of floating distances returned by the AABB slab test. A fully negative interval is possible. | [Geometry and intersections](/MLEDocs/versions/c1abea3de165/systems/math/geometry-and-intersections/) |

`min<T>()` forwards `std::numeric_limits<T>::min()`. For a floating type, that is the smallest positive normal value, not the most negative finite value. `as<T>` is an unchecked `static_cast`.

## Result categories

The enum ordering makes category boundaries operational. This list is grouped by `isError`, not by how an application might choose to react.

- Non-error results: `OK`, `TIMEOUT`, `SWAPCHAIN_NOT_VISIBLE`, `FRAME_SKIP`, `NOT_READY`, `CURSOR_NOT_INSIDE_WINDOW`, and `DISABLED`.
- Error results: `NOK`, `INVALID_ARGUMENT`, `OUT_OR_RANGE`, `NOT_FOUND`, `FAILED_TO_OPEN`, `ALLOCATION_FAILED`, `FAILED_TO_CREATE`, `INVALID_TYPE`, and `OAL_ERROR`.

The misspelled `OUT_OR_RANGE` name is the actual identifier in this commit. Keep it unchanged in code and diagnostics.

## Evidence boundary

The ThreadPool, 2D geometry, string, justification, and rectangle-packing test files establish the behaviors they explicitly assert. They do not collectively certify every alias or enum listed here. Items without a matching assertion are source-observed lookup facts. Return to the owner page before relying on lifetime, thread, failure, serialization, or edge semantics.
